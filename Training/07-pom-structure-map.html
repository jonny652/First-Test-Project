Playwright · Page Object Model

How this project's test files fit together

The Page Object Model (POM) keeps test code tidy by splitting it into jobs. The spec says what to check; page objects hold where things are and how to use them; a shared base page holds behaviour common to every page; the fixture wires it all together; and utils are reusable helpers. Follow the arrows to see who uses whom.

Fixture — builds & hands over
Page Object — locators + actions

How one test runs, start to finish

Trace the very first test — “the heading is correct” — through the files.

  1. You run the specPlaywright opens first-test.spec.ts and sees the test needs nbsHomePage and dysonManufacturerPage.
  2. The fixture builds the toolstest-options.ts runs new NbsHomePage(page) and new DysonManufacturerPage(page) — each super(page) pulls in the shared BasePage setup — then hands them to the test.
  3. beforeEach navigates, step by stepgoto() → closePopup() (from BasePage) → search("dyson") → openManufacturersTab() → openDysonManufacturer().
  4. The assertion uses a locatorexpect(dysonManufacturerPage.heading).toContainText("Dyson") — the test reads where the heading is from the page object.
  5. Utils handle the heavy liftingThe visual & accessibility tests call applyVisualRegression() and generateAccessibilityReport() straight from utils/.
